# SodAudit — 职责分离(SoD)冲突检查工具

找出"一个人（或串通的多人）集齐某条业务流程全部关键权限"的授权组合，
并给出冲突证据链和最小修正方案。

## 运行

```bash
dotnet run              # 以今天为基准日检查
dotnet run 2026-12-01   # 指定基准日（影响临时代理是否生效）
```

## 模型：权限的四层叠加

每个用户的有效权限 = 以下四类授权来源的并集，**每条权限都保留来源链**：

| 层 | 类型 | 可撤销单元 |
|---|---|---|
| 角色继承 | `DirectRole` — 直接分配的角色，沿角色 DAG 展开继承链 | 一条角色分配 |
| 部门授权 | `DepartmentGrant` — 部门成员自动获得角色/权限 | 一条部门授权 |
| 临时代理 | `Delegation` — 带时间窗，可标记"业务已批准" | 一条代理记录 |
| 审批流配置 | `ApprovalFlow` — 审批节点等效于动态授予审批权限 | 一条审批流规则 |

权限点带系统归属（ERP / Finance / VendorMaster / HR / CRM），
SoD 规则天然跨系统——冲突往往要跨几个系统才能凑齐。

## 检测逻辑（ConflictDetector）

1. **单人冲突**：有效权限 ⊇ 规则权限集 → 冲突。
2. **冲突分级**：若拿掉所有"代理来源"后冲突消失，说明冲突仅由临时代理造成——
   代理经业务批准 → 仅备案；未批准 → 限期整改。其余为结构性冲突。
3. **串通风险**：只沿关系边（上下级 / 同组 / HR备案的亲属利益关系）检查用户对，
   两人权限并集凑齐规则且各自单独不冲突 → 串通风险。
   上下级互补属岗位设计性固有风险，报告中汇总提示而非逐条刷屏。
4. **最小修正**：打破冲突只需剥夺规则中**任意一个**权限；
   剥夺某权限的代价 = 撤销授予它的全部授权单元（同一权限可能多条来源叠加）。
   按代价升序给出主方案与备选；含代理来源时提示"可终止代理或待其到期"。

## 模拟数据（DataSeeder，固定种子可复现）

中型企业：180 人 / 12 部门 / 18 角色（含继承链）/ 18 权限点 / 5 系统 /
10 条 SoD 规则 / 4 条代理（1 条已过期，用于验证时间窗过滤）/ 3 条审批流。

埋入的典型场景：

1. 财务经理兼任供应商管理员 → 新建供应商+付款审批（跨系统，即审计发现的原型）
2. 高级采购员被审批流配置补上 PO.Approve → 自建自批
3. 部门授权历史遗留 → 整部门"自购自收"、出纳"改账户+放款"
4. 临时代理两例：一个经批准（备案）、一个口头安排（限期整改）
5. 薪酬专员被错配薪酬经理角色 → 薪资自调自批
6. 夫妻分持 Vendor.Create / Payment.Approve → 串通风险

## 文件

- `Models.cs` — 领域模型（权限/角色/用户/部门授权/代理/审批流/关系/SoD规则）
- `PermissionResolver.cs` — 四层叠加解析 + 来源链追踪
- `ConflictDetector.cs` — 冲突检测、分级、串通分析、最小修正
- `DataSeeder.cs` — 模拟企业数据
- `Program.cs` — 审计报告输出
